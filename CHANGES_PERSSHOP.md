# Интеграция Pers Shop — отчёт (backend + админка + сайт)

Репозиторий: `manu-main` (backend, Node/Express + SQLite).
Ничего из старого не удалено: `data/games.json`, старый поставщик ALU
(`services/supplier.js`), старые заказы, пользователи, чеки — не тронуты.

## ВАЖНО: что НЕ входит в эту фазу

- **Категории Steam** (`steamTopup: true` в ответе Pers Shop) — синхронизация
  их сейчас пропускает (`summary.skippedSteam`), потому что механика заказа
  там другая (сумма в USD + логин, без offerId). Можно добавить отдельно.
- **Товары с 3+ полями заказа** — синхронизируются и хранятся, но помечаются
  `unsupportedFields: true` и НЕ показываются на сайте, потому что текущий
  фронтенд знает только про 2 поля (UID + сервер). Как только пришлёте
  фронтенд сайта — доработаю форму заказа под произвольные поля.
- ~~Рекламные плашки и страница покупки VIP~~ — **сделано** (фаза 2, см. раздел
  "Сайт" ниже), после того как вы прислали архив сайта.
- Раздел **не трогаем**: проблема "цены могут сбрасываться после перезапуска"
  (она в том, что `data/games.json` читается из статического файла, а правки
  через админку никогда не пишутся обратно в файл) — оставлено как есть, как
  вы и просили.

## БАЗА ДАННЫХ

- Новая таблица `supplierGames` — создаётся автоматически при первом запуске
  (`CREATE TABLE IF NOT EXISTS`, как и остальные). **Отдельная миграция не нужна**,
  ничего разрушающего нет, старые таблицы не тронуты.
- `settings.persshop` — новое поле в уже существующей строке настроек, тоже
  без миграции (объект просто больше не пустой).
- У пользователей (`users`) появляются (лениво, при первом использовании)
  поля `purchasedVipPercent`, `vipPurchasedAt` — не требуют миграции, просто
  отсутствуют (`undefined`) у всех, кто ещё не покупал VIP.
- У заказов (`orders`) появляются поля `provider`, `supplierOrderId`,
  `supplierOrderNumber`, `supplierStatus`, `supplierError` — только у новых
  заказов через Pers Shop, старые заказы этих полей не имеют и не должны.

## DEPLOY — пошагово для VPS с PM2 + nginx

Ниже — универсальная последовательность. Точные пути и имена (`pm2` process
name, папка сайта в nginx) могут отличаться — если не уверены, пришлите вывод
`pm2 list` и содержимое конфига nginx (`/etc/nginx/sites-enabled/...`), сверю.

**1. Backend (там, где сейчас лежит `manu-main` на VPS):**
```bash
cd /var/www/manushop-backend        # ваш реальный путь к backend-репозиторию
git pull                            # или залейте файлы вручную, если деплоите не через git
nano .env                           # добавить/проверить:
#   PERSSHOP_API_KEY=<ваш ключ из личного кабинета persshop.com>
#   PERSSHOP_BASE_URL=https://persshop.com/api/v1   (можно не указывать — это значение по умолчанию)
#   WEBHOOK_BASE_URL=https://api.manushop.store      (проверьте — уже должно быть задано для старого поставщика ALU)
npm install                         # новых npm-зависимостей НЕТ, но не помешает
pm2 restart manushop-backend        # или тот process name, что покажет `pm2 list`
pm2 logs manushop-backend --lines 50   # убедиться, что стартовало без ошибок
```
Миграция базы — **делать не нужно**: новая таблица `supplierGames` создаётся
сама при первом запуске (`CREATE TABLE IF NOT EXISTS`), как и все остальные.

**2. Проверка, что backend жив:**
```bash
curl https://api.manushop.store/api/health
# ожидаем: {"ok":true}
```

**3. Первая синхронизация каталога Pers Shop** — через вкладку "Pers Shop" в
обновлённой админке (кнопка "Синхронизировать каталог"), либо curl:
```bash
curl -X POST https://api.manushop.store/api/admin/supplier/sync \
  -H "Authorization: Bearer <ваш_админский_JWT_токен>"
```
Токен — тот же, что использует админка (можно скопировать из `localStorage`
браузера, ключ `ms_admin_token`, после входа в админку).

**4. Регистрация webhook** (один раз) — кнопка "Зарегистрировать webhook" в
той же вкладке, либо:
```bash
curl -X POST https://api.manushop.store/api/admin/supplier/webhook/register \
  -H "Authorization: Bearer <ваш_админский_JWT_токен>"
```
Это делать нужно **только один раз** после первого деплоя (или заново, если
поменяли домен/поддомен backend'а).

**5. nginx** — если `WEBHOOK_BASE_URL` совпадает с доменом, который уже
проксирует `/api/*` на backend (как для старого поставщика ALU), отдельно
менять конфиг nginx **не нужно** — `/api/webhook/persshop` пройдёт по тому же
правилу, что и остальные `/api/*` маршруты. Проверить это можно так:
```bash
grep -A5 "location /api" /etc/nginx/sites-enabled/*
```
Если там `proxy_pass` на ваш backend (например, `http://localhost:4000`) —
всё уже работает, ничего менять не нужно. Если нет — пришлите этот конфиг,
дам точную правку.

**6. Админ-панель и сайт** — оба чистый HTML/JS без сборки, просто замена
файла `index.html` на том хостинге, где они сейчас лежат (судя по имени
архива `deploy-*.zip`, сайт похож на Netlify — тогда это либо `git push` в
привязанный репозиторий, либо повторный drag-and-drop zip-архива в Netlify
Deploys, в зависимости от того, как у вас настроено). Если сайт и админка
раздаются иначе — пришлите, как именно, дам точные команды.

**7. Тестовый заказ** — см. раздел "ТЕСТ" ниже.

## ТЕСТ

Теперь можно проверять прямо через обновлённую админку (вкладка "Pers Shop"),
без curl:

- Вкладка **Pers Shop** → "Синхронизировать каталог" → появляются товары,
  во всплывающем уведомлении видно сколько создано/обновлено/пропало.
- Открыть один товар → поставить фото, включить "Включена" и "Опубликована
  на сайте" → "Сохранить".
- `GET /api/games` (или сам сайт, когда пришлёте репозиторий) → товар
  появился в общем списке наравне со старыми играми.
- Сделать заказ этим товаром → вкладка **Заказы** → у заказа статус
  "Выполняется у поставщика" / "Выполнен" и пометка "(Pers Shop)".
- Вкладка **Пополнения** → заявка с `purpose=vip` показывает "🔥 VIP 3%" в
  колонке "Тип" ещё до подтверждения.
- После подтверждения такой заявки → вкладка **Пользователи** → у
  пользователя в колонке VIP появляется "🔥 Куплен 3%".
- `GET /api/stats/public` (или лента на сайте) — в каждой записи появилось поле `price`.
- Открыть сайт → под шапкой плашка "❤️ Поддержать администрацию", через 30 сек
  сама переключается на "🔥 VIP — скидка до 10%" (и обратно).
- Нажать на плашку VIP → выбрать уровень (например 3% / 45 сомони) → откроется
  та же форма оплаты, что и обычное пополнение, сумма уже стоит и недоступна
  для правки.
- Личный кабинет → карточка VIP → кнопка "Купить VIP" / "Повысить уровень
  покупкой" всегда доступна, даже если у магазина не настроены автоматические
  VIP-уровни по сумме покупок.
